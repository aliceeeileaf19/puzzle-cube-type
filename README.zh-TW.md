# puzzle-cube-type

一顆七階魔術方塊，自己轉出字母。

**[線上 demo →](https://aliceeeileaf19.github.io/puzzle-cube-type/)**

貼紙顏色在開場決定，之後**永不改變**。正面出現的每一個字母，都是靠合法轉層轉出來的
——跟你在實體方塊上用手轉的是同一種動作。拖著轉一圈就會發現背後沒有機關：三面白、
三面黑，從頭到尾就只有這樣。

CSS 與 JavaScript 合計 31 KB（gzip 約 10 KB），其中不少是註解。零依賴、免建置、
不用 WebGL 也不用 canvas，純 CSS 3D transform。

## 這不是 mosaic 產生器

Mosaic 工具是把**一整片方塊陣列**排好，從正面看去近似一張圖。這裡是單顆方塊當顯示器，
而且限制嚴格得多——沒有任何東西被重新上色：

|              | puzzle-cube-type       | 典型 mosaic 工具   |
| ------------ | ---------------------- | ------------------ |
| 方塊數量     | 一顆                   | 幾十到幾千顆       |
| 貼紙顏色     | 永久固定               | 依目標指定         |
| 目標怎麼達成 | 一串解出來的合法轉層   | 通常直接設定顏色   |
| 可驗證的命題 | 亮貼紙總數恆定不變     | —                  |

最後一列才是重點。打開 demo 的 console：亮貼紙的數量從第一步到最後一步都是 147。
排列不會憑空生出或消滅貼紙，所以「總數恆定」就是「字母是被**搬**到位、不是被畫上去」
的證明。

## 原理

### 讓整件事成立的那一個恆等式

把正面的格子用欄 `i`、列 `j` 編號，都是 `-3` 到 `3`。定義

- `C_i` ＝ 轉 `x = i` 這一層（垂直板），**只會動到正面第 i 欄**
- `R_j` ＝ 轉 `y = j` 這一層（水平板），**只會動到正面第 j 列**

然後看它們的交換子：

```
[C_i , R_j]  =  C_i · R_j · C_i⁻¹ · R_j⁻¹
```

- 既不在第 `i` 欄、也不在第 `j` 列的格子，四步都碰不到它。
- 在欄上但不在列上的格子，被 `C_i` 帶離正面、再被 `C_i⁻¹` 帶回原位；中間的 `R_j`
  伸不到它去的地方。
- 在列上但不在欄上的格子，對稱地同理。

所以整串下來**只有交叉的那一格 `(i, j)` 會換貼紙**，其餘 48 格完全不動。
49 個格子全部驗證成立。

這就是整個解算器。有了「能單獨改一格、又不擾動其他格」的工具，就能一格一格修，
而且永遠不會拆掉自己剛修好的部分。

關鍵補充：**「只改一格」是排列本身的性質**，跟貼紙目前在哪無關。所以工具表在啟動時
探測一次（約 150ms）就永久有效。把搜尋範圍放寬到 180° 變體與 z 層共軛之後，可以得到
**約 1200 個 4 步或 6 步的工具**——這很重要，因為每一格會有好幾種不同的三循環可選。

### 為什麼是三面白、三面黑

貼紙不能跨越塊型軌道。角塊貼紙永遠只能到面的四個角、邊塊只能到邊框、中心塊只能到內部。
所以每個軌道都必須自己備足兩種顏色。

方便的事實：**每個軌道在六個面上的分布都是均勻的**（軌道大小 ＝ 每面格數 × 6）。
所以「整面上色」就會讓每個軌道剛好一半白一半黑，完全不需要逐片調配。

26 個字母的最壞情況：

| 軌道                | 貼紙數 | 正面佔格 | 最多需白 | 最多需黑 | 三白三黑給你 |
| ------------------- | -----: | -------: | -------: | -------: | -----------: |
| 角塊                |     24 |        4 |    4（E） |    4（C） |      12 / 12 |
| 邊翼塊 t=1          |     48 |        8 |    8（B） |    8（X） |      24 / 24 |
| 邊翼塊 t=2          |     48 |        8 |    8（B） |    8（X） |      24 / 24 |
| 邊中塊              |     24 |        4 |    4（D） |    4（X） |      12 / 12 |
| T 心塊（內／外）    |  24 ×2 |      4×2 |        2 |        4 |      12 / 12 |
| X 心塊（內／外）    |  24 ×2 |      4×2 |    4（X） |    4（B） |      12 / 12 |
| 斜心塊（左／右）    |  24 ×2 |      4×2 |    2（V） |    4（B） |      12 / 12 |
| 面心塊              |      6 |        1 |    1（B） |    1（A） |        3 / 3 |

貼紙共 294 片，白 147、黑 147。硬下限其實只要白 41、黑 49，所以這個配色在每個軌道
都有約 3 倍餘裕。

> 一個七階特有的細節：48 片斜心塊會分成**左手性與右手性兩個各 24 片的軌道，彼此永不
> 互通**，必須當成兩個獨立軌道來算。五階根本沒有斜心塊。

因此「哪三面是白的」純屬外觀。預設是 `top`、`right`、`back`——刻意讓**正面是黑的**：
還原後是一塊乾淨的黑色網格，字母的白像素一格一格轉上去；而預設視角看到的兩個面是白的，
立方體的體積感就是這樣來的。

### 解算器

1. **貪婪下降**：試遍 42 種單步，取最能縮小與目標漢明距離的那一步，只要還有改善就繼續。
   一步能重寫一整列或一整欄，所以能便宜地把差距拉近大半。
2. **逐格修補**：對每個還錯的格子，套用一個能給出所需顏色的單格工具。已經正確的格子
   不可能被擾動。
3. **洗貼紙池**：如果某格可用的三循環剛好全是同一色，就套一步「保證不會動到正面」的
   轉動（`z = 3` 以外的任何 z 層）再重試。

成本：每個字母 **4–12ms**。長度：`ALICEILEAF` 平均 **28 步**、`WILLIAM` **17 步**、
整個字母表 **31 步**。

同一個字母連續出現時是 **0 步**，因為真方塊本來就不需要動。步數太少時會先補幾步不動
正面的轉動再重解，這樣看得到方塊在動，字母卻不受影響。

## 驗證

以下全部可以從 demo 的 `window.CubeType` 自己重跑。

| 檢查項目                                         | 結果                 |
| ------------------------------------------------ | -------------------- |
| 26 個字母逐格吻合目標                            | 26 / 26              |
| 282 個任意 49 位元目標（全白、全黑、密度 5–95%） | 0 失敗               |
| 上述目標的步數                                   | 中位數 40，4 至 85   |
| 140 次實際動畫轉場，模型 vs 目標                 | 0 不吻合             |
| DOM transform vs 內部模型                        | 漢明距離 0           |
| 亮貼紙總數（任何時刻）                           | 恆為 147             |

所以：三面白三面黑的配色下，**任意 7×7 黑白點陣看起來都能只用合法轉層在單面上達成。**
上面的軌道計算說明了為什麼兩種顏色都不會不夠；282 個案例是實證，不是可達性的形式證明。

元件本身在執行時也會自我檢查：每拼完一個字母就把正面跟目標逐格比對，只要有一格不符就
`console.warn`。至今沒有觸發過。

## 用法

```html
<link rel="stylesheet" href="cube-type.css">

<div class="cube-type">
  <div class="cube-type__block" data-word="HELLO"></div>
</div>

<script src="cube-type.js"></script>
```

`.cube-type` 底下每一個 `.cube-type__block` 都會變成獨立的一顆方塊，循環它的
`data-word`。只定義了 `A`–`Z`，其他字元會被忽略。

| 屬性                 | 放在          | 效果                     |
| -------------------- | ------------- | ------------------------ |
| `data-word="…"`      | `__block`     | 要循環的字母             |
| `data-labels="off"`  | `.cube-type`  | 隱藏文字與步數那一行     |
| `data-reset="off"`   | `.cube-type`  | 隱藏 Reset 鈕            |

互動：**拖曳**旋轉、**點一下**跳下一個字母、**Reset** 回到還原狀態。`Space`（暫停）
與 `R`（還原）只在 `<body class="cube-standalone">` 時綁定，所以嵌進別的頁面時不會
搶走鍵盤。

捲出畫面會自動暫停，並且遵守 `prefers-reduced-motion`（完全不做動畫）。

### 可調參數

`cube-type.js` 裡：`N`（階數，5 或 9 也可以，要提供對應的 `GLYPHS`）、`LIGHT_FACES`、
`FAST` / `TAIL` / `HOLD`（節奏）、`MIN_MOVES`、以及 `GLYPHS` 本身。
`cube-type.css` 裡：`--ct-s` 決定一個像素多大，其餘全部依它縮放。

### 從程式碼指定目標

`bitsOf('A')` 回傳 49 位元（row-major），而 `solve(state, target)` 接受任意 49 位元
陣列。字母只是這個通用能力的第一個使用者。

## 限制

- **49 個像素、只有兩色。** 字母、圖示、符號沒問題；照片放不進來。
- **每顆約 500 個 DOM 節點**（218 顆小方塊、294 片貼紙）。一頁放兩顆很輕鬆，放十幾顆
  就不行。只有正在轉的那一層會動，這是它還能維持便宜的原因。
- **還沒有實體方塊記譜輸出。** 解算器產出的是 `(軸, 層, 方向)`，把它對映成標準大方塊
  記譜（`3R'`、`2U2`）讓人能照著在真的七階上轉，是最明顯的下一步，目前還沒做。
- 瀏覽器會節流背景分頁的計時器，所以 demo 不在前景時看起來會很慢。那是瀏覽器，不是
  解算器。

## 前人相關工作

方塊動畫播放器（[Roofpig](https://github.com/larspetrus/Roofpig)、
[AnimCubeJS](https://animcubejs.cubing.net/animcubejs.html)）能重播記譜，但不建構圖案。
Mosaic 產生器（[Tessellate](https://github.com/adlrwbr/Tessellate)、
[Roman-/mosaic](https://github.com/Roman-/mosaic)）用一片方塊陣列拼圖。
大方塊解算器（[RCube](https://github.com/ShellPuppy/RCube)）同樣用交換子搬中心塊，
但目標是還原而不是達成指定圖案。我沒有找到在固定貼紙配色下、把單顆方塊當排版顯示器
使用的前人作品。
